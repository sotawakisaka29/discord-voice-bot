# Discord Voice Clone Bot

自分の声を使って Discord で応答するボイスボットを、確認可能で安全な小さな手順に分けて作るプロジェクトです。

## 目的

- 自分の許可した音声データのみを使って音声モデルを用意する。
- Discord の音声チャンネルで、指定した入力に対して自分の声の音声を再生できるようにする。
- 秘密情報・音声データ・生成物をリポジトリに含めない。

## 作業方針

1. **一度に一つのステップだけ進めます。** そのステップの完了条件を確認してから、次へ進みます。
2. **各ステップで、何をするか・なぜするか・完了条件を明示します。** 実行結果も短く報告します。
3. **より安全・簡単・低コストな選択肢があれば、実施前に提案します。** 仕様や費用に影響する選択は、勝手に決めません。
4. **やり取りと実装は簡潔にします。** 必要最小限のトークン、ファイル、依存関係で進めます。
5. **機密情報は絶対に記録・共有しません。** API キー、Discord トークン、個人音声、学習済みモデル、生成音声は Git に追加しません。
6. **外部サービスであなたの操作が必要な場合は、画面名・入力内容・確認方法まで具体的に案内します。** パスワードやトークンの値を尋ねたり、このチャットに貼るよう求めたりしません。
7. **各セクションの完了後に Git の commit と push を提案します。** 実際の `git add`、`commit`、`push` は、必ずあなたの明示的な確認を得てから実行します。
8. **不明点・失敗・費用が発生しうる操作は止めて共有します。** 推測で不可逆な変更や外部公開は行いません。

## 進め方

各ステップは次の形式で扱います。

| 項目 | 内容 |
| --- | --- |
| 目的 | このステップで得る成果 |
| 実施内容 | 変更・コマンド・外部操作 |
| 完了条件 | 次へ進めることを確認する基準 |
| あなたの操作 | 必要な場合のみ、具体的な手順 |
| Git | commit / push 前に確認 |

## 想定ロードマップ

0. プロジェクト初期化と開発ルールの確定
1. 実現方式の選定（ローカル音声合成または外部音声 API、費用・品質・PC 性能を比較）
2. Discord Developer Portal でボットを作成し、必要な権限を設定
3. ローカル開発環境と秘密情報の設定
4. テキストを受け取り、音声を生成する最小機能の実装
5. Discord 音声チャンネルへの接続・再生
6. 自分の音声データの準備と、選定方式に応じた音声モデル設定
7. エラー処理、権限確認、ログ、停止方法の整備
8. 少人数のテストサーバーで検証
9. 運用手順と必要ならデプロイ方法を整備

## 音声と利用上の注意

- 使用するのは自分の声、または明確な許可を得た声だけにします。
- ボットであることと、合成音声であることを利用者に分かるようにします。
- Discord と選定する音声サービスの利用規約、API 利用料金、サーバーのルールを確認します。
- 公開サーバーでの運用前に、アクセス制限・コマンド制限・停止手段を必ず確認します。

## 現在の状態

macOSの音声合成、Discord音声チャンネルへの接続、読み上げキューを実装済みです。今後は GPT-SoVITS をローカルで動かし、手動で用意した声モデルを追加します。

## 声プロフィールの管理

- 声の登録、参照音声の収集、学習は手動で行います。
- 利用できる声は `voices.json` で管理します。音声・モデル本体は Git に追加しません。
- `/voices` で登録済みの声を確認できます。
- サーバー管理権限を持つ人は `/setvoice voice:<ID>` で、サーバー全体の読み上げる声を切り替えられます。
- 現在は `engine: "macos"` の声だけを読み上げに利用できます。GPT-SoVITSモデルは導入後に同じプロフィール構造へ追加します。
